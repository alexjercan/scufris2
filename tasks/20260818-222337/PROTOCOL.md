# Scufris protocol

## Conventions

- JSON examples show model-to-extension native tool arguments and extension results.
- IDs are generated by Scufris and treated as opaque by the model.
- Strings are UTF-8 with LF line endings.
- Byte limits are checked after UTF-8 encoding, not by JavaScript character count alone.
- Unknown fields are rejected.
- Native tools never accept shell commands, executable paths, repository paths, URLs, or desktop commands.
- Delegation targets use opaque IDs discovered below user-configured roots.

## Harness defaults

| Harness | Model                | Thinking |
| ------- | -------------------- | -------- |
| Pi      | `openai/gpt-5.6-sol` | `medium` |
| Claude  | `opus`               | `xhigh`  |

The foreground orchestrator can override project, model, and thinking in each spawn request. Scufris does not infer project check commands.

## Job IDs and locations

Job ID:

```text
[a-z0-9]{12}
```

Feature name:

```text
scufris-<job_id>
```

Files:

```text
${XDG_STATE_HOME:-$HOME/.local/state}/scufris/jobs/<job_id>/job.json
${XDG_STATE_HOME:-$HOME/.local/state}/scufris/jobs/<job_id>/prompt.md
${XDG_STATE_HOME:-$HOME/.local/state}/scufris/jobs/<job_id>/status
${XDG_STATE_HOME:-$HOME/.local/state}/scufris/jobs/<job_id>/report.md
```

Tmux target:

```text
socket:  scufris
session: jobs
window:  job-<job_id>
```

Every tmux invocation selects the dedicated socket explicitly. Every tmux and sprout subprocess removes inherited `TMUX` and uses a Scufris-owned socket directory. Never touch the user's default tmux server.

## Agent tools

### `scufris_agent_projects`

Lists opaque Git project IDs accepted by spawn. It accepts no input fields and returns only IDs, never filesystem paths.

### `scufris_agent_spawn`

Starts one delegated worker in a generated isolated worktree.

Input:

```json
{
  "harness": "pi",
  "project": "personal/example",
  "instructions": "Investigate the failing check and implement the fix.",
  "model": "openai/gpt-5.6-sol",
  "thinking": "medium"
}
```

Schema:

- `harness`: required enum `pi | claude`.
- `project`: optional opaque ID returned by `scufris_agent_projects`. Omit it to use the current Git repository.
- `instructions`: required nonempty string, maximum 256 KiB UTF-8.
- `model`: optional nonempty string, maximum 200 bytes, no control characters.
- `thinking`: optional enum `off | minimal | low | medium | high | xhigh | max`.

Omitted values use the harness defaults. Explicit input wins. The adapter validates thinking support. The harness validates its model name.

Result:

```json
{
  "job_id": "8k2m4p6q9s1v",
  "state": "running",
  "harness": "pi",
  "feature": "scufris-8k2m4p6q9s1v",
  "message": "Worker started in an isolated worktree. It runs independently."
}
```

Spawn transaction:

1. Resolve the explicit discovered project ID, or the current Git root when the ID is omitted.
2. Verify the selected directory is an exact Git root.
3. Generate job and feature IDs.
4. Create the worktree with `sprout new`.
5. Create the job directory with mode 0700.
6. Write immutable `job.json` and `prompt.md` with mode 0400.
7. Create empty `status` and `report.md` with mode 0600.
8. Create the exact tmux window with a fixed helper invocation and the generated job ID only.
9. The helper reads job data and replaces itself with the selected harness using argument arrays. Model text never enters the tmux shell command.
10. Add in-memory ownership only after launch succeeds.
11. Roll back created resources on any earlier failure.

### `scufris_agent_list`

Input:

```json
{}
```

Result:

```json
{
  "jobs": [
    {
      "job_id": "8k2m4p6q9s1v",
      "harness": "pi",
      "state": "working",
      "summary": "running project checks",
      "feature": "scufris-8k2m4p6q9s1v"
    }
  ]
}
```

Returns owned jobs only. It does not discover or adopt orphans.

### `scufris_agent_inspect`

Input:

```json
{
  "job_id": "8k2m4p6q9s1v",
  "include_report": true
}
```

Schema:

- `job_id`: required generated ID.
- `include_report`: optional boolean, default false.

Result:

```json
{
  "job_id": "8k2m4p6q9s1v",
  "state": "review-ready",
  "summary": "revision committed and checks passed",
  "window_alive": true,
  "events": [
    "working: running project checks",
    "review-ready: revision committed and checks passed"
  ],
  "report": "..."
}
```

Rules:

- Event output is capped at the last 100 valid lines and 32 KiB.
- Report is omitted unless requested.
- Included report is capped at 1 MiB.
- Pane transcript is not returned.

### `scufris_agent_send`

Input:

```json
{
  "job_id": "8k2m4p6q9s1v",
  "message": "Address the review feedback, commit one fix revision, rerun checks, and report review-ready again."
}
```

Schema:

- `job_id`: required generated ID.
- `message`: required nonempty single-line UTF-8 string, maximum 16 KiB, no NUL, CR, or LF.

Result:

```json
{
  "job_id": "8k2m4p6q9s1v",
  "delivery": "submitted",
  "message": "Text was pasted once and Enter was sent once. Harness processing is not acknowledged."
}
```

Mechanics:

- Resolve only an owned exact tmux target.
- Use a unique tmux buffer.
- Load literal bytes, paste once, wait 300 ms, send Enter once, and delete the buffer.
- Never retry text or Enter.
- Return an error for any tmux failure.
- A successful return means submitted, not processed.

Messages over 16 KiB are rejected.

### `scufris_agent_stop`

Input:

```json
{
  "job_id": "8k2m4p6q9s1v"
}
```

Result:

```json
{
  "job_id": "8k2m4p6q9s1v",
  "state": "stopped"
}
```

Stop sequence:

1. Mark stopping in memory.
2. Send Escape once.
3. Wait two seconds.
4. Submit `/quit` for Pi or `/exit` for Claude once through a tmux buffer.
5. Wait up to five seconds for the harness process to exit.
6. Kill the exact tmux window if it remains.
7. Mark stopped.

Stop is idempotent. It does not land, delete the worktree, or delete job evidence.

## Job files

### `job.json`

Immutable extension-owned record:

```json
{
  "version": 1,
  "job_id": "8k2m4p6q9s1v",
  "harness": "pi",
  "model": "openai/gpt-5.6-sol",
  "thinking": "medium",
  "feature": "scufris-8k2m4p6q9s1v",
  "landing_branch": "master",
  "landing_sha": "0123456789abcdef0123456789abcdef01234567",
  "created_at": "2026-08-21T07:30:00Z"
}
```

Do not store prompt text, credentials, environment values, or absolute paths in this record.

### `prompt.md`

- Written once before launch.
- Maximum 1 MiB.
- Mode 0400.
- Contains the complete initial request, job paths, status grammar, report rules, Git rules, and a requirement to follow repository instructions and run applicable checks.
- The worker must not modify it.

### `status`

- Append-only.
- Maximum 256 KiB.
- Each complete line maximum 2 KiB including LF.
- UTF-8 and LF only. CRLF is malformed.
- Empty lines are malformed.
- Only complete newline-terminated lines are parsed.

Grammar:

```text
<state>: <summary>\n
```

States:

```text
working
needs-decision
blocked
review-ready
done
failed
```

Summary rules:

- Nonempty.
- One line.
- No C0 controls or DEL.
- Human-readable and safe for model context.
- No credentials, raw logs, absolute paths, or transcript content.

Semantics:

- `working`: sparse nonterminal progress.
- `needs-decision`: worker cannot choose safely.
- `blocked`: external condition prevents progress.
- `review-ready`: coding revision is committed, synchronized, checked, and documented.
- `done`: terminal result that needs no code review or landing.
- `failed`: terminal failure.

`review-ready` is not terminal. Feedback returns the same worker to work. A later `review-ready` starts a new round.

### `report.md`

- Worker-written before the related `review-ready`, `done`, or `failed` line.
- Maximum 1 MiB.
- Complete replacement is allowed; append-only is not required.
- Must contain a concise result, changed files or findings, and verification evidence.

For `review-ready`, the report lists:

- The result of `sprout sync`.
- Each check command selected after reading repository instructions.
- Each check outcome and any relevant limitation.
- The current landing and feature SHAs.
- Any matching project task record updated with the same evidence when repository instructions require one.

This report is human review evidence. Scufris reads Git state directly instead of trusting machine-readable claims from the worker.

## Status polling

Per job, the extension keeps a byte offset and an incomplete trailing buffer.

A cycle:

1. Stat `status` without following a replacement symlink.
2. Reject size over 256 KiB.
3. Read bytes from the saved offset and join the prior incomplete tail.
4. Split complete LF-terminated byte frames.
5. Validate UTF-8, grammar, and limits for each complete frame.
6. Retain an incomplete final byte frame for the next cycle.
7. Advance the offset through every complete frame, including malformed frames.
8. Emit each valid line once and each new malformed-frame error once.

A changed inode or a file size below the saved offset violates append-only storage. Report one protocol error, do not interpret replacement bytes, and do not stop the worker.

Malformed, unknown, or oversized input:

- Produces one protocol-error follow-up for that newly observed condition.
- Is not interpreted as a state.
- Does not stop the worker automatically.
- Does not repeatedly notify for unchanged bytes.

If the exact worker window disappears without `done:` or `failed:`, emit:

```text
failed: worker exited without terminal status
```

This is an extension event for the foreground model. It is not appended to the worker-owned status file.

## Review protocol

Preconditions for every round:

- Feature worktree is clean.
- `sprout sync <feature>` completed.
- Current landing SHA is an ancestor of feature SHA.
- `report.md` records synchronization, applicable checks, results, limitations, and current revisions.
- `review-ready:` is newer than the prior round.

Review snapshot:

```json
{
  "round": 2,
  "landing_sha": "0123456789abcdef0123456789abcdef01234567",
  "feature_sha": "89abcdef0123456789abcdef0123456789abcdef",
  "requested_view": "since-base"
}
```

Request review through Plannotator's public Pi event API:

```ts
pi.events.emit("plannotator:request", {
  requestId,
  action: "code-review",
  payload: {
    cwd: worktreePath,
    defaultBranch: landingBranch,
    diffType: "since-base",
  },
  respond: handleReviewResponse,
});
```

Use the plain event-channel string. Do not import Plannotator internals. The callback receives a handled result after the browser decision:

```json
{
  "status": "handled",
  "result": {
    "approved": true,
    "feedback": "",
    "annotations": []
  }
}
```

Review types:

- Initial and final review: `since-base`.
- Optional focused fix review: `last-commit`.
- Approval from `last-commit` is ignored. Start a new `since-base` request for approval.

Outcomes:

- Handled `since-base` result with `approved: true`: candidate approval.
- Handled result with feedback: send feedback to the same worker.
- Exit or empty feedback without approval: no approval.
- Error, unavailable, or malformed response: no approval.

Candidate approval validation:

1. Require structured `approved: true` from the current `since-base` request.
2. Require unchanged landing and feature SHAs.
3. Require clean worktree.
4. Require target ancestry.
5. Read the oldest feature-only commit subject and reject an empty, multiline, control-containing, or over-200-byte value.
6. Run `sprout land <feature> --dry-run -m <subject>`.
7. Recheck revisions.
8. Run `sprout land <feature> -m <subject>`.

Pass the subject as one argument without a shell. Do not push.

## Widget tools

Dashboardd is presentation-only. No dashboard query tool exists.

All commands invoke `dashboardctl` directly with argument arrays and a five-second process timeout. Scufris parses protocol version 2 responses and preserves stable dashboardd error codes.

During `session_start`, Scufris calls `dashboardctl discover` once, bounds the response to 64 KiB, validates the catalog, and caches it for that Pi session. It then registers widget tools dynamically. The open-tool schema is a discriminated union of exact discovered widget IDs, variants, options, and input envelopes. A failed discovery leaves agent tools available, emits one notification, and registers no widget tools. `/reload` retries discovery. There is no model-facing discover tool.

Dashboardctl JSON remains the process protocol. Model-facing widget results use concise text and retain bounded structured details. Raw discovery JSON does not enter model context.

### `scufris_widget_open`

Input:

```json
{
  "widget_id": "cpu",
  "variant_id": "full",
  "options": {},
  "inputs": {},
  "presentation": "focus"
}
```

Schema:

- `widget_id`: required discovered ID.
- `variant_id`: required variant for that widget.
- `options`: optional object containing only options applicable to that variant, with discovered types, limits, and choices.
- `inputs`: optional object containing only inputs applicable to that variant. Required inputs are required by the generated schema, and each envelope type is the exact discovered type.
- `presentation`: optional enum `focus | tile`, default `focus`.

Result:

```json
{
  "widget_id": "cpu",
  "variant_id": "full",
  "surface_id": "surface-4",
  "state": "open"
}
```

Model text:

```text
Opened cpu full view as surface-4.
```

Every call creates a new surface. No reuse or deduplication.

### `scufris_widget_update`

Input:

```json
{
  "surface_id": "surface-4",
  "presentation": "tile"
}
```

At least one of `inputs` or `presentation` is required. `inputs` replaces the complete direct-input map. Options are immutable. The surface must be owned by the current Pi session.

### `scufris_widget_list`

Input:

```json
{}
```

Returns dashboardd protocol version 2 surface metadata. The extension marks which returned IDs it owns.

### `scufris_widget_focus`

Input:

```json
{
  "surface_id": "surface-4"
}
```

Requires an explicit surface ID owned by the current Pi session.

### `scufris_widget_close`

Input:

```json
{
  "surface_id": "surface-4"
}
```

Requires an explicit surface ID owned by the current Pi session. Closing deletes the surface and runtime instance. An already externally closed tracked surface is removed from ownership and is not closed again.

## External widget close event

When a tracked surface is absent from one polled `dashboardctl list` result:

```json
{
  "customType": "scufris-widget-event",
  "content": "Widget surface surface-4 was closed outside Scufris.",
  "display": true,
  "details": {
    "surface_id": "surface-4",
    "event": "closed"
  }
}
```

Send as a custom message without `triggerTurn`. Show one compact notification. Remove ownership immediately. Do not reopen or retry close.

## Dashboardd wire examples

Open request generated by dashboardctl:

```json
{ "version": 2, "command": "open", "widget_id": "cpu", "variant_id": "full" }
```

Successful response:

```json
{ "version": 2, "status": "ok", "result": { "surface_id": "surface-4" } }
```

Failed response:

```json
{
  "version": 2,
  "status": "failed",
  "error": { "code": "surface_not_found", "message": "surface does not exist" }
}
```

The wire limit is 64 KiB including LF. One request and one response use one Unix connection.

## Versioning

- Native tool and job protocol changes are breaking until version 1 is released.
- `job.json` and dashboardd wire versions are independent.
- Reject unknown major versions.
- Do not add compatibility aliases or deprecated fields.
