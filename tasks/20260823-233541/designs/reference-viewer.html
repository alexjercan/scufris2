Every roguelike deckbuilder inherits the same design tax: a shuffled deck means some hands will be bad, and bad hands are supposed to be part of the tension. The trouble starts when a bad hand quietly turns into a dead hand, a draw with nothing in it that changes the fight you are currently losing.

Curve design is the usual lever. A deck's curve is the distribution of what a card costs against what it does, plotted across a typical run length rather than a single match. Get the curve wrong early and the deck spends its first ten turns doing arithmetic instead of playing a game.

cited by scufris

A deck under fifteen cards should almost never carry more than two non-answers at any point in its curve. Past that threshold the dead draw rate compounds faster than card quality can offset it, no matter how good the top end is.

Slay the Spire's answer was aggressive thinning: cards that remove themselves or their neighbors from the deck, so the curve tightens as the run goes on instead of staying fixed at its starting shape. Other entries in the genre lean on tutors instead, cards that fetch a specific answer on demand, which fixes the dead draw problem locally but adds its own variance if the tutor itself gets drawn dead.

Neither fix is free, and that is the actual design question: which kind of variance are you willing to keep, the shape of the deck or the shape of the search for an answer inside it. Whatever the choice, it has to be made on purpose, early, before the card pool grows large enough that curve problems hide inside it.

00:00Hi, I'm Priya Natarajan, I work on systems design at a small roguelike studio, and today I want to talk about a problem that shows up the moment you let the computer build your decks for you: card synergy that either does nothing, or does too much.

02:14The failure mode on one end is a deck that feels flat. Cards sit next to each other and never interact, so every run plays the same regardless of what you drew. The failure mode on the other end is a deck that snowballs the instant two specific cards land in the same hand, and every other run feels like a coin flip for whether that pair showed up.

05:47We model synergy as a weighted graph. Every card is a node. Every pair of cards that interact gets a scored edge, positive for combos, negative for cards that actively work against each other. The generator samples clusters from that graph, which is the part that actually changes how a run feels.

09:30The number that mattered most in playtesting wasn't the average synergy score, it was the tail. We cap how many high-weight edges can appear in the same deck, so a run can still find a strong combo, but it can't stack three of them and break the curve entirely. That cap is the whole balance knob.

13:02Here's a deck the generator produced under that cap. Watch the highlighted cards: three of them share a resource-conversion theme, which is enough to feel intentional, but the rest of the deck stays generically useful so a bad draw early doesn't end the run before it starts.

16:50That's the core of it: model the interactions explicitly, then budget them like any other scarce resource. Thanks for watching, the slides and the sampling code are both linked below.
