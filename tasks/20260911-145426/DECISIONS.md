# Decisions

Where this implementation differs from
`native-pi-scufris-clone/tasks/20260911-120039/DESIGN.md`, and why. The design
is a plan written against `768b035`; this branch is built on `a81ad73` and
reconciles rather than copies. Every deviation below is deliberate.

## `AgentHolder` has two values, not three

The design's state machine names a `handing-over` step between `managed` and
`terminal`. The type has two values.

A third value would have to be observable, and there is nothing to observe: a
grant is only sent after the child is reaped (`waitpid` returned), so no
surface can see the service between the two states. Adding the value would put
a word on the wire that is true for no measurable interval, and every surface
would need a label for it.

The waiting itself is still there. It is the `control.lease_acquire` handler
blocking until the reap, which is what
`a_terminal_takes_the_agent_and_gives_it_back` observes.

## `AgentSession` gained `parent`

`agent.hello.session` carries the session file. The design assumed the service
could derive the lineage from the file alone. It cannot: a fork's header names
its parent, and reading another process's session file to find that out makes
the service depend on Pi's on-disk format.

The agent sends `parent` because the agent is the one Pi told. The service
records it and nothing parses a session file.

## Catch-up is built where the conversation is, not where the lease is

The design puts catch-up pages in the lease handler. They are built in
`send_catch_up` beside the conversation ring instead.

The ring is the only thing that knows what was said and in what order, and it
is already bounded at 200 entries with a stable sequence. Paging from anywhere
else would have meant a second copy of the bound.

## `nix/terminal.nix`, not a second output from `nix/launcher.nix`

The design says the terminal launcher is "a launcher output". `nix/launcher.nix`
returns one derivation, and `flake.nix`, the checks, and the Home Manager
module all consume it as one. Making it return an attribute set would have
changed three consumers to add a fourth thing. A new file adds one.

## `lineage prune --keep <days>` is a number

The design writes `--keep 30d`. The flag takes a number of days. One type, no
parser, and `--dry-run` for the rehearsal. A duration string would be a parser
and an error message for a flag whose only unit is days.

## `scufris-terminal` composes no extensions

The design does not say either way. The launcher passes no `--extension`: the
terminal extension comes from the checkout's `.pi/extensions/scufris-terminal`.

Two compositions would be two agents. A launcher that composed the extension
would also load it in a checkout that already has it, and the second copy
would take the lease the first one holds. The cost is that the launcher only
does something in a checkout that carries the extension, which
`docs/src/dev/staging.md` says.

## `suspend-owner` is skipped whenever the conversation owns the work

The design skips it "on `agent.handoff`". It is skipped whenever the holder is
the conversation.

A terminal that exits cleanly releases the lease and is never sent a handoff
message; there is nothing left to send it to. Under the narrower rule every
clean exit would suspend the conversation's jobs, which is the opposite of
what moving the agent is for. The next holder's `recover` adopts what is
running, and a holder that crashes leaves the same jobs running for the same
reason.

## No `--debug-lease` alias

The design keeps `--debug-lease` as an alias "for one release so a unit
generated by the previous generation still starts". There is no such unit. The
proof-of-concept commit `6af196f` is on the `native-pi-scufris-clone` branch
and on no tag and no release, so nothing deployed has ever used that name. The
alias would be debug naming shipped into production for a compatibility that
does not exist. The `service-closure` check pins the flag's absence.

## No product version bump

The design's Phase 6 asks for "the version bump that
`tools/release/check_versions.py` checks". That script checks protocol parity
across the Rust, TypeScript, and Swift mirrors. All three are 11 and it
passes.

The product version bump is `RELEASE.md` step 2: its own reviewed commit that
also moves the `[Unreleased]` entries under a dated heading and rewrites the
comparison links. Every bump in the history is such a commit. Putting one in a
feature commit would make the next release commit conflict with itself. The
entries are under `[Unreleased]`, and the protocol-11 `Changed` entry is what
makes the next release a minor bump.

## G3 passed with a qualification

Gate G3 is recorded as `pass*`. `ctx.switchSession` from a `session_start`
dispatch works, but the switch starts a session, which fires `session_start`,
which dispatches again: the unguarded run performed 3560 switches in 25
seconds. The condition carried into production is that `/scufris attach` runs
only when the current session is not already the lineage fork, which is what
`attach forks the lineage once, and never asks twice` pins. No fallback was
needed.
